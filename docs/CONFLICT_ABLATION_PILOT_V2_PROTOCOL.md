# Engineering pilot v2: scope-aware conflicting evidence

Author: Brian Doutey, independent researcher (no institutional affiliation)

Status: frozen before API calls. These 30 items are excluded from confirmation.

Pilot v1 was operationally successful but all three serious arbiters—including
the frozen keyword rule—scored 90/90, creating a known ceiling. V2 preserves
the same models, visible evidence policy, balanced candidate positions, closed
choice interface, and analysis gates. It changes only the evidence packets.

Every packet now requires resolving scope, chronology, or negation. Surface
words associated with strong provenance also appear in invalid candidates, and
surface words associated with weak provenance may appear in the history of the
valid candidate. Examples include a document labelled current that was later
superseded, and a proposed replacement whose rejection means the original
record remains controlling.

Conditions remain deterministic hash choice, the unchanged frozen keyword
rule, non-reasoning OpenAI classification, and JEV classification. All arbiters
see identical anonymized packets. A question-level path requires three correct
stage selections.

Engineering gates are: at least 29/30 complete; JEV and OpenAI each at least
81/90 correct stages; correct candidate positions exactly 30/30/30; hidden
reasoning rejected. The keyword rule has no accuracy gate because its failure
under scope reversal is part of the intended ablation, not a system failure.

Success permits freezing a disjoint 300-question dataset without changing the
generator, prompts, policy, or rules. This remains a synthetic provenance task,
not proof that provenance guarantees factual truth or resists forged metadata.

The project is independent, unfunded personal work by Brian Doutey, with no
affiliation with TypeSafe and no external influence.
